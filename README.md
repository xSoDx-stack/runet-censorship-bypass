**АнтиЧебурнет** — расширение Manifest V3 для браузеров на базе Chromium. Оно устанавливает PAC-скрипт в настройки браузера и по его правилам направляет отдельные сайты напрямую (`DIRECT`) или через прокси.

Расширение предназначено для Google Chrome, Microsoft Edge, Brave, Яндекс.Браузера, Opera и Vivaldi. Фактическая совместимость зависит от версии и политики конкретного браузера; минимальная поддерживаемая версия Chromium — 102.

> **Важно:** это не VPN. Расширение управляет только трафиком браузера, не влияет на другие приложения и не гарантирует доступность каждого сайта, анонимность или сокрытие IP для соединений, которые PAC оставляет прямыми.

## Что умеет расширение

- Загружать и применять PAC от «Антизапрета» или «Антицензорити».
- Работать только с добавленными пользователем сайтами и собственными прокси.
- Загружать готовый пользовательский PAC по прямой ссылке.
- Для выбранного домена принудительно включать прокси, прямое подключение или снова передавать решение PAC.
- Подключать прокси HTTP, HTTPS, SOCKS4 и SOCKS5, в том числе локальные Tor и WARP.
- Проверять доступность пользовательских прокси и поддерживать прокси с логином и паролем.
- Импортировать и экспортировать списки доменов в формате `.txt`.
- Открывать официальный сервис проверки блокировок Роскомнадзора с адресом текущей страницы, уже подставленным в форму; CAPTCHA и отправка запроса остаются ручными.
- Показывать локальный журнал ошибок PAC, прокси и авторизации с копированием отдельных записей и экспортом журнала.
- Предупреждать о потере контроля над настройками прокси или сбоях обновления PAC.

Какие именно адреса пойдут через прокси, определяет выбранный PAC-источник и пользовательские правила. Списки провайдеров могут обновляться с задержкой, содержать лишние адреса или не включать недавно ограниченный ресурс.

## Быстрый старт

1. Установите расширение и откройте его окно с панели браузера.
2. На вкладке **PAC** выберите источник. Для первого запуска обычно достаточно «Антизапрета» или «Антицензорити» — добавлять собственный прокси для них не обязательно.
3. Дождитесь сообщения об успешном применении PAC.
4. Если отдельный сайт открывается неправильно, перейдите на вкладку **Сайты** и выберите для него:
   - **Прокси** — принудительно использовать настроенный пользовательский прокси;
   - **Напрямую** — не использовать прокси;
   - **По PAC** — вернуть решение выбранному PAC-скрипту.
5. Диагностика доступна во вкладках **Логи** и **Тест**.

После изменения правил расширение пересобирает и повторно применяет PAC автоматически.

## Режимы PAC

| Режим | Назначение | Что учитывать |
| --- | --- | --- |
| **Антизапрет** | Маршрутизация по PAC проекта «Антизапрет» | Состав правил и работоспособность прокси зависят от внешнего поставщика |
| **Антицензорити** | Альтернативный PAC с собственной базой адресов и прокси | PAC может быть значительно больше и обрабатываться дольше |
| **Только свои сайты** | Проксирование только доменов, которые пользователь добавил вручную | Требуется хотя бы один доступный пользовательский прокси или локальный Tor |
| **Свой PAC по ссылке** | Использование готового PAC из указанного URL | Источник получает запрос на загрузку; поверх его правил применяются пользовательские настройки расширения |
| **Отключить** | Освобождение настроек прокси | Трафик возвращается к настройкам браузера или системы |

Активный PAC автоматически обновляется примерно раз в четыре часа, пока браузер может выполнять фоновые задачи. При переключении источника расширение загружает и применяет PAC выбранного провайдера. Если обновление не удалось, ранее успешно применённый PAC не заменяется повреждёнными или пустыми данными; причина сохраняется в журнале.

Для встроенных провайдеров установлен лимит загрузки **25 МиБ**, для пользовательской ссылки — **10 МиБ**. Пользовательский PAC должен содержать функцию `FindProxyForURL`. Для внешних адресов разрешён только HTTPS; HTTP можно использовать лишь для локальных и частных сетевых адресов. Выбирайте доверенный источник: изменённый или вредоносный PAC способен направить браузерный трафик через посторонний прокси.

## Пользовательские прокси и Proxy Or Die

Проверка прокси временно применяет тестовую конфигурацию, выполняет контрольный HTTPS-запрос через проверяемый сервер, а затем восстанавливает предыдущие настройки. Результат проверки подтверждает доступность в момент теста, но не гарантирует дальнейшую стабильность или доступ ко всем сайтам.

Режим **Proxy Or Die** запрещает откат к прямому соединению, когда для адреса уже выбран прокси, но прокси недоступен. Это снижает риск непреднамеренного прямого подключения, однако может полностью заблокировать загрузку ресурса. Домены, явно помеченные пользователем как прямые, продолжают открываться напрямую.

Оператор прокси может видеть адреса подключений и метаданные трафика, а при незашифрованном HTTP — и содержимое. Используйте только серверы, которым доверяете.

## Индикация и диагностика

Значок расширения отмечает домены вкладки, для которых использование прокси удалось определить по известному адресу прокси или пользовательскому правилу. Это диагностическая подсказка, а не точный аудит каждого соединения: одна страница может одновременно загружать основной документ напрямую, а изображения, API или другие поддомены — через прокси.

Во вкладке **Логи** сохраняются ошибки загрузки и применения PAC, проверки прокси, авторизации и потери контроля над настройками. Записи можно фильтровать, копировать по одной или экспортировать целиком.

Если сайт не открывается:

1. Проверьте дату последнего обновления PAC и вкладку **Логи**.
2. Попробуйте другой встроенный PAC-источник.
3. Если используется собственный прокси, запустите его проверку во вкладке **Прокси**.
4. Проверьте, не управляет ли прокси другое расширение или политика браузера.
5. Временно отключите **Proxy Or Die** только для диагностики: это может разрешить прямое подключение.

## Приватность и сетевые обращения

В проекте нет аналитических SDK, рекламных счётчиков или отправки истории посещений разработчику. Настройки, правила, сведения о прокси и диагностический журнал хранятся локально в `chrome.storage.local`.

При этом расширение не работает полностью офлайн и выполняет необходимые сетевые обращения:

- загружает PAC с серверов выбранного провайдера или пользовательского URL;
- при добавлении или явной проверке пользовательского прокси обращается через него к тестовому адресу Cloudflare `1.1.1.1`;
- открывает внешние сайты только по команде пользователя из меню или интерфейса, например реестр блокировок, веб-архив или страницу справки;
- передаёт браузерный трафик через прокси, выбранные PAC-скриптом или пользователем.

Если прокси требует пароль, учётные данные входят в локальную конфигурацию в открытом виде: браузерный API не предоставляет расширению системное защищённое хранилище секретов. Пароли не выводятся в журнал и не отправляются разработчику. Для чувствительных прокси рекомендуется отдельная учётная запись с минимальными правами.

## Разрешения браузера

| Разрешение | Зачем используется |
| --- | --- |
| `proxy` | Установка и обновление PAC-конфигурации браузера |
| `storage`, `unlimitedStorage` | Локальное хранение PAC, настроек, правил и журнала |
| `alarms` | Периодическая фоновая проверка обновлений PAC |
| `tabs` | Работа с доменом активной вкладки и индикация на значке |
| `webRequest` | Диагностика сетевых и прокси-ошибок |
| `webRequestAuthProvider` | Передача логина и пароля пользовательскому прокси |
| `contextMenus` | Команды расширения в контекстном меню страницы |
| `notifications` | Включаемые пользователем уведомления о сбоях |
| `<all_urls>` | Загрузка PAC по выбранному адресу, применение правил ко всем сайтам и проверка сетевых ответов |

Доступ `webNavigation` не запрашивается. Разрешение на работу в приватных окнах пользователь включает отдельно в настройках браузера.

## Установка из исходного кода

### Требования

- Node.js 20 или новее;
- npm 9 или новее;
- браузер на базе Chromium 102 или новее.

### Сборка

```bash
git clone https://github.com/xSoDx-stack/runet-censorship-bypass.git
cd runet-censorship-bypass
npm install --prefix extensions/chromium/runet-censorship-bypass
npm run build
```

Готовое распакованное расширение появится в каталоге:

```text
extensions/chromium/runet-censorship-bypass/build/extension-full
```

### Установка в браузер

1. Откройте `chrome://extensions/` или соответствующую страницу расширений вашего браузера.
2. Включите **Режим разработчика**.
3. Нажмите **Загрузить распакованное расширение**.
4. Выберите каталог `build/extension-full`, указанный выше.
5. После следующей сборки нажимайте **Обновить** на карточке расширения, чтобы браузер загрузил изменения.

## Команды разработчика

```bash
npm run build          # проверить версию и собрать build/extension-full
npm run lint           # запустить ESLint
npm test               # запустить тесты
npm run version:check  # проверить синхронность версии во всех файлах
npm run bump:patch     # увеличить patch-версию и синхронизировать файлы
```

Единственный источник версии проекта — поле `version` в корневом `package.json`. Если оно было изменено вручную, выполните `npm run version:sync`. Проверка синхронности также автоматически запускается перед сборкой, тестами и линтингом.
